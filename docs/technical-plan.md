# CX Launcher 技术方案

日期：2026-10-03。状态：首版技术基线；已实施 0.4.0 低透明度流体背景、鼠标搅动、玻璃卡片扫光与页头流光，具体实测及未完成验收见 [实施记录](implementation-status.md)。以下原始目标继续作为验收依据。

## 1. 目标与范围

用户已确认仅支持 Windows 10/11。工程建立在 `C:\cxluncher`。

核心目标：手动添加本地游戏路径，集中展示并启动；界面精致，启动快速，空闲资源占用低，离线可用。

首版按 x64 构建。Windows 11 为主要验证平台，Windows 10 22H2 x64 为兼容性测试目标，不宣称覆盖所有 Windows 10 历史版本。.NET 的官方系统支持随 Windows 生命周期变化；“应用兼容性实测通过”和“系统仍处于官方支持期”分别记录。

## 2. 技术决策

| 项目 | 选择 | 原因 |
| --- | --- | --- |
| 编程语言 | C# | 适合 Windows 文件、快捷方式、窗口和进程管理，维护成本适中 |
| 运行平台 | .NET 10 LTS | 采用受支持的长期支持版本，具体 SDK 补丁在搭建时锁定 |
| 界面 | WPF + XAML | 原生桌面框架，具备样式、模板、数据绑定和图形能力，无需浏览器渲染层 |
| 组织方式 | MVVM + CommunityToolkit.Mvvm | 分离界面和逻辑，减少属性通知、命令样板代码 |
| 视觉实现 | 自定义 ResourceDictionary 和控件模板 | 只实现所需组件，统一颜色、间距、圆角和交互状态 |
| 数据 | System.Text.Json + 本地文件 | 当前规模无需数据库服务或 ORM，便于备份和导出 |
| 图片 | 本地封面 + 按显示尺寸生成缩略图 | 控制解码成本和内存，避免依赖网络 |
| 游戏启动 | ProcessStartInfo + Windows Shell API | 正确处理可执行文件与快捷方式的不同语义 |
| 测试 | 核心逻辑自动测试 + Windows 人工验收 | 重点验证持久化、路径及启动参数，界面和兼容性用实机验证 |

WPF 是 Windows 桌面 UI 框架，不意味着所有控件都由传统 Win32 标准控件绘制。界面外观由模板和视觉设计决定，可以实现现代游戏库界面。

### 候选方案比较

以下是针对本项目的工程判断，不是同一环境下的性能跑分。

| 方案 | 适配情况 | 本项目决策 |
| --- | --- | --- |
| C# + WPF | Windows 集成直接，支持细致定制；需处理 .NET 运行时分发 | 采用 |
| Rust + Tauri + Web 前端 | 跨平台和 Web 界面有优势；Windows 上仍使用 WebView2，需维护两类技术栈 | 当前只支持 Windows，暂不引入 |
| Electron | Web UI 生态成熟；随应用分发 Chromium 与 Node.js | 不符合本项目优先控制资源开销的取向 |
| C++ + Qt / Win32 | 可做高效桌面程序；需要更多原生开发和 UI 工程投入 | 当前功能规模不值得增加维护成本 |

WPF 是否实际更省内存，需要以本应用的 Release 构建验证，不能从语言或框架名称直接推导。

## 3. 首版功能

1. 添加游戏：文件选择和拖入 `.exe` / `.lnk`，自动填写可用的名称和图标。
2. 编辑条目：名称、目标路径、本地封面、分类、收藏；可执行文件允许设置启动参数和工作目录。
3. 游戏库：封面卡片、紧凑列表、名称搜索、分类、收藏、最近启动排序。
4. 启动：点击按钮或键盘操作启动；即时反馈成功提交或具体失败原因。
5. 路径失效处理：保留条目，提示重新定位，不静默删除。
6. 数据保存：重启恢复游戏库、窗口设置和显示偏好；提供导入导出。
7. 移除条目仅修改游戏库，不删除游戏文件。

首版将“最近启动”定义为成功向系统提交启动请求，不等于游戏进入可玩状态。部分游戏会转交其他启动器，不能仅用最初进程是否退出判断游戏是否仍在运行。

后续候选：Steam 等协议导入、自动扫描、在线封面、托盘、可靠的游戏时长统计。首版不依赖这些能力。

## 4. 启动与数据规则

### 启动

- `.exe` 保存结构化的路径、工作目录与参数字段，不拼接 `cmd /c` 或 PowerShell 命令。
- 路径和工作目录独立传入；验证中文、空格及特殊字符路径。默认工作目录为可执行文件所在目录，允许覆盖。
- `.lnk` 保留快捷方式自身的目标、参数和工作目录语义，通过 Windows Shell 启动。首版不在其外部再叠加参数。
- 图标读取、路径检查和缩略图处理在后台完成，避免慢磁盘或失效网络路径卡住界面。
- 默认普通权限运行。需要管理员权限时展示系统或应用错误，不自动提升整个启动器。
- 短时间重复点击同一启动按钮做防抖；不宣称已经完成跨启动器的“游戏运行中”检测。
- 启动器退出不结束游戏，不将游戏加入随父进程退出而终止的作业对象。

### 本地存储

默认目录：`%LOCALAPPDATA%\CXLauncher\`。

```text
library.json         游戏库，包含 schemaVersion
settings.json        用户偏好
backups/             有上限的有效配置备份
covers/              用户封面副本
cache/thumbnails/    可重建的缩略图缓存
logs/                有大小与数量上限的诊断日志
```

游戏字段：`id`、`name`、`targetType`、`targetPath`、`arguments`、`workingDirectory`、`coverId`、`category`、`favorite`、`addedAt`、`lastLaunchedAt`。类型约束区分快捷方式和可执行文件的可编辑字段。

写入串行化；先写同目录临时文件，再替换正式文件，保留最近有效备份。解析或版本校验失败时提供恢复入口，不能用空库覆盖损坏文件。单实例运行，第二次打开激活已有窗口，避免多实例覆盖配置。

导入时校验结构和版本，预览合并结果；导入不会自动执行游戏。封面复制到应用数据目录，防止原始图片移动后失效。日志默认不记录完整启动参数。

数百至一千条游戏先用 JSON 验证；若未来增加大量历史记录或复杂查询，再按实测迁移至 SQLite。

以下结构已建立，并增加 `scripts/`、解决方案、SDK 锁定文件及测试隔离输出 `.artifacts/`。

```text
C:\cxluncher\

  src/
    CXLauncher/
      Views/
      ViewModels/
      Models/
      Services/
      Themes/
      Assets/
```

首版一个应用项目加一个测试项目，不引入后端服务或插件框架。服务按职责分为游戏启动、游戏库保存、封面缓存与用户设置；只有存在测试替换或平台边界时才增加接口。

## 6. 性能设计与验收

以下均为工程目标，不是已测结果。基准采用记录了 CPU、内存、磁盘与系统版本的 Windows x64 测试机，SSD、至少 8 GB 内存，Release 构建、无调试器。测试库含 500 个条目和本地缓存封面，另用 1,000 条验证滚动扩展性。

| 项目 | 初始目标 | 测量口径 |
| --- | --- | --- |
| 常规冷启动 | 可操作界面 ≤ 1.5 秒 | 系统重启后首次运行，排除安装过程；首次初始化另列 |
| 热启动 | 可操作界面 ≤ 0.8 秒 | 退出重开，重复 10 次记录中位数与最大值 |
| 空闲内存 | 私有工作集争取 ≤ 120 MB | 首页稳定 30 秒、常规可见封面数量；同时记录专用字节 |
| 空闲 CPU | 平均低于 0.5% | 无操作稳定 60 秒，记录工具和归一化口径 |
| 搜索 | 输入到结果稳定 ≤ 100 ms | 500 条数据，包含输入去抖耗时 |
| 启动反馈 | 按钮视觉反馈 ≤ 100 ms | 不包含游戏加载耗时 |

设计措施：

- 先呈现窗口和库元数据，再加载可见区域缩略图。
- 列表虚拟化与容器回收；封面网格按可见行虚拟化。普通 WrapPanel 不视作已实现虚拟化，需验证实际生成容器数量。
- 限制并发图片解码和缓存预算，不加载全部原图；切换页面取消失效任务。
- 不做全盘扫描或持续高频进程轮询，窗口隐藏时暂停动画。
- 仅使用必要的短动画，减少大面积透明、模糊和多层阴影；不引入常驻动态背景。

首个可运行版本立即测量，不等所有视觉效果完成后再处理性能问题。

## 7. 分发

- 主推小体积的框架依赖版本，目标机器需有匹配的 .NET 10 Desktop Runtime；安装流程检测依赖，缺少时明确提示安装。
- 另提供自包含便携版，携带运行时，可离线解压运行；代价是更大下载体积。用户数据默认仍保存在 LocalAppData。
- 分别报告压缩包体积、解压后体积以及额外运行时需求，避免将小体积应用文件等同于完整安装成本。
- 不预设包体积保证；不把 Native AOT 或激进裁剪作为首版 WPF 的体积优化前提。

## 8. 实现顺序与验收

1. 准备 SDK，建立最小 WPF 工程、主题资源和游戏模型，完成空状态页面。
2. 完成添加、编辑、保存、重启恢复和真实启动，验证带空格与中文路径、`.lnk`、参数、工作目录。
3. 完成卡片和列表、封面、搜索与收藏，检查键盘操作及不同 DPI。
4. 验证缺失路径、权限错误、重复点击、损坏 JSON 恢复；通过小型测试程序捕获参数和工作目录进行启动集成测试，不依赖实际游戏作为自动测试。
5. 测量性能，在 Windows 10/11 环境分别执行兼容性验证，再打包两种分发版本。

规划时本机只有 .NET 6.0.11 运行时。实现阶段已在项目 `.tools/` 内准备并锁定 .NET SDK 10.0.401，当前完成 Release 编译、100 项自动检查及两种 0.4.0 分发包。ZIP 与校验文件交付到 `dist`；Windows 10、多 DPI 和性能目标最终验收待完成。
